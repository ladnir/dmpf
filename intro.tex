\section{Introduction}

Distributed point functions (DPFs) let two parties hold short keys whose
evaluations share a point function \cite{dpf,dpf2,fss}.
Applications include pseudorandom correlation generators (PCGs), private
information retrieval, and private set operations.
Many of these applications need several hidden positions at once.
Running $t$ independent DPFs solves that problem, but expanding a
length-$N$ output costs $O(tN)$ local work.

A distributed multi-point function (DMPF) can reduce this expansion cost.
The challenge in our setting is key generation: neither party knows the
complete index list.
Cuckoo layouts assign each input to one of several candidate bins and use a
sparse DPF for each bin \cite{fssBatchCodes,cuckooDmpf,dmpf}.
The layout reduces total leaf work, but constructing the secret assignment
requires oblivious table access, collision handling, and repair.
We focus on the total nonlinear work of this distributed setup.

\paragraph{Generic construction.}
Our main construction is Waterfall Cuckoo.
It samples public hashes first and combines an inexpensive occupancy scan
with a fixed number of complete augmentations.
After deduplication and dummy padding, the candidates have the same uniform
distribution for every input support.
A hidden-permutation scatter then initializes the sparse DPFs.
We prove correctness and semi-honest simulation in the ideal-subprotocol
model, with a once-per-setup routing error and separate subprotocol losses.

Setup fixes the addresses, routing, and DPF leaf seeds.
Expansion supplies only new payloads.
The default $t=16$ profile uses 64 physical bins and $4N$ leaf work.
A second profile uses 320 bins and $3N$ leaf work.
The profiles share one protocol and proof, exposing a setup--expansion
tradeoff rather than separate constructions.

\paragraph{Ring-LPN specialization.}
Reverse Cuckoo instead chooses the placement first and programs compatible
public hashes. This reduces leaf expansion to $2N$ but leaks information
about the support.
We retain it only for random Ring-LPN supports under an explicit
leakage-robust decisional assumption.
The attack study examines support search, decoding, and algebraic approaches;
it is evidence for that assumption, not a generic security proof.
The concrete degree-two hash analysis gives more than 40 bits of batch
correctness for the filtered $N_{\mathsf R}=2^{20}$ caller distribution.

\paragraph{Measured performance.}
The end-to-end measurements use Reverse Cuckoo over two prime fields.
They predate the mask, support-filter, permutation, and evaluator-seed
updates, and the AES rekeying described here; they do not validate the
complete current recipe.
At $n=2^{20}$, the Goldilocks field
$q=2^{64}-2^{32}+1$ gives 1.81 million OLEs/s and 12.99 MB per expansion.
The Fp31 field gives 2.71 million OLEs/s and 6.51 MB.
Against the reported FHE baseline at the same degree and fields, throughput
improves by $6.57\times$ and $8.75\times$, respectively; expansion
communication falls by $13.60\times$ and $27.12\times$.
These comparisons exclude one-time setup.

\sectionref{sec:eval} gives setup costs, OLE-to-triple normalization, and
the smaller-domain sum-of-DPFs comparison, where faster expansion need not
mean lower communication. Waterfall's costs are modeled, not measured here.

\paragraph{Organization.}
We first define the reusable DPF and DMPF interfaces and develop Waterfall
as the generic construction.
Bucketing and big-state alternatives describe other setup--state tradeoffs.
The Ring-LPN application then motivates Reverse Cuckoo, its leakage
assumption, and the measured specialized pipeline.
