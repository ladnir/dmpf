
\section{Cuckoo-Based DMPF}\label{sec:cuckoo}


Cuckoo hashing assigns each input to one of a small number of candidate
bins, with at most one input per bin \cite{cuckoo}.
Applied to DMPFs, it gives one sparse single-point function per bin
\cite{fssBatchCodes,cuckooDmpf,dmpf}. We review this layout because it
separates two tasks: reducing local expansion and constructing the secret
placement. Waterfall addresses the second task.

For this description, fix distinct addresses $A_1,\ldots,A_t\in[0,N)$;
duplicate aggregation and dummy padding are handled by the full construction.
Input rows use $i\in[t]$, hash choices use $j\in[w]$, and physical bins use
$b\in[0,m)$. Public hashes $h_j:[0,N)\to[0,m)$ define a
\emph{position map} $P\in\{0,1\}^{[0,N)\times[0,m)}$ by
\[
 P_{x,b}:=[b\in\{h_1(x),\ldots,h_w(x)\}].
\]
A valid placement assigns distinct columns $c_1,\ldots,c_t\in[0,m)$
such that $P_{A_i,c_i}=1$ for every $i\in[t]$.
Not every hash tuple admits such a placement. Parameters must bound this
failure probability over the sampled hashes for each fixed input set.

Given a valid placement, define $U\in\{0,1\}^{[0,N)\times[0,m)}$ by
$U_{A_i,c_i}:=1$, with all other entries zero. Each column of $U$ has weight
at most one. For payloads $B\in\mathbb G^t$, define
$D\in\mathbb G^{[0,N)\times[0,m)}$ by $D_{A_i,c_i}:=B_i$, with all other
entries zero. Thus each column of $D$ is a point map or the zero map, and
\[
 \sum_{i\in[t]:A_i=x}B_i=\sum_{b\in[0,m)}D_{x,b}.
\]

The public sparse set for column $b$ is
$S_b:=\{x\in[0,N):P_{x,b}=1\}$. Write $S:=(S_b)_{b\in[0,m)}$.
Only entries in $S_b$ need to be expanded in that column.

In the example, summing the columns gives
$(B_2,0,B_1,0,0,B_3,0,0)$. The public sparse sets are
\[
 S_0=\{0,1,4,6\},\quad S_1=\{2,3,5,6\},\quad
 S_2=\{0,2,4,7\},\quad S_3=\{1,3,5,7\}.
\]
Using full-domain DPFs for all $m$ columns would cost $mN$ leaf work.
Restricting each column to its sparse set instead gives
\[
 \sum_{b\in[0,m)}|S_b|
 =\sum_{x\in[0,N)}\bigl|\{h_1(x),\ldots,h_w(x)\}\bigr|
 \leq wN.
\]
Equality holds when every address has $w$ distinct candidate bins, as in the
example and in Waterfall's partitioned layout. For constant $w$, this
reduces leaf work from $tN$ to $O(N)$.

\paragraph{Address Translation.}
A standard DPF over a compressed column needs the rank of $A_i$ within the
increasingly ordered set $S_{c_i}$, rather than the ambient address $A_i$.
That zero-based rank is
\[
 A'_i:=\sum_{x\in[0,A_i)}P_{x,c_i}\in[0,|S_{c_i}|).
\]
For example, $A_1=2$ has rank zero in $S_1$, whose compressed payload
column is $(B_1,0,0,0)$. Directly computing this rank with secret $A_i,c_i$
requires a secret-index prefix count in the public position map.

The permutation-based layout of~\cite{dmpf} supplies the bin and its local
address together. Assuming $m\mid wN$, put $f:=wN/m$ and use a permutation
\[
 \pi:[w]\times[0,N)\longrightarrow[0,m)\times[0,f).
\]
Writing $(h_j(x),a_j(x)):=\pi(j,x)$, a point placed via choice $j$ uses
local address $a_j(x)$. Each bin has exactly $f$ slots because $\pi$ is a
bijection. This avoids the prefix count, but requires evaluating the
permutation on secret inputs in MPC.

\paragraph{Sparse DPF.}
Our sparse DPF accepts the ambient address $A_i\in S_{c_i}$ directly and
returns a map indexed by that public set. It therefore removes the
address-translation permutation from this layout. The remaining tasks are
to sample suitable hashes and find a valid secret placement; the sparse DPF
alone does not resolve either task.

\paragraph{Iterative Insertion.} Up to this point we have ignored the question of how to choose the column $c_i\in\{h_1(A_i),...,h_w(A_i)\}$ that the pair $(A_i,B_i)$ will be mapped to. Moreover, note that this must be performed within MPC as the $A_i,B_i$ values will be seceret shared. In the plaintext setting the standard approach is to iteratively construct the set $c$ which is initially empty. Starting with $A_1$, we arbitrarily choose $c_1\in\{h_1(A_1),...,h_w(A_1)\}$. For $A_i\in \{A_2,...,A_t\}$, we again choose some $c_i\in\{h_1(A_i),...,h_w(A_i)\}$. If the value of $c_i$ is already being used by come $c_j$, then we ``evict'' $A_j$ from column $c_i$ and place $A_i$ there instead. We then reinsert $A_j$ using some other hash function value and continue this eviction processes until all items are inserted or some threshold of attempts are made, at which point the insert abort. 

In MPC, the occupied-bin lookup, eviction, and stopping condition depend on
secret addresses. Implementing these operations directly can dominate setup.
Waterfall Cuckoo retains the sparse-column layout but uses a fixed circuit:
an occupancy scan places most rows, and a bounded number of complete
augmentations repairs the placement. The next section specifies that circuit
and bounds its routing error.
