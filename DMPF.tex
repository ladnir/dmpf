

\section{Distributed Multi-Point Function}\label{sec:dmpf}


\sectionref{sec:dpf} defined a reusable DPF whose setup fixes one index and
whose expansions supply many payloads.  A distributed multi-point function
(DMPF) provides the same interface for at most $t$ indices.  Running $t$
independent DPFs realizes this interface, but costs $O(tN)$ local work.

Let $\mathcal X_N:=[0,N)\cup\{N\}$, where $N$ is a dummy address.  For
$A\in\mathcal X_N^t$ and $B\in\mathbb G^t$, define the map
\[
 \mathsf{mp}_{N,t}(A,B)(x):=
 \sum_{i\in[0,t):A_i=x}B_i,
 \qquad x\in[0,N).
\]
Rows with address $N$ make no contribution.  Equal real addresses contribute
their payload sum.  \figureref{fig:dmpfFunc} defines the reusable ideal
functionality targeted by the constructions below.
Calls have inputs in their declared domains; no input-membership test is
included in the protocol costs.
As for the single-point functionality, the corrupt party $P_b$,
$b\in\{0,1\}$, chooses its output share.

\begin{figure}[H]\vspace{-0.3cm}\small
	\centering
	\fbox{ \begin{minipage}{.95\textwidth}\raggedright
    Public parameters are $\kappa,N,t\in\mathbb N$ and a finite additive group
    $\mathbb G$.  The functionality maintains state $(A,q)$, initially
    undefined.\\
    \medskip

    $\mathcal F_{\mathsf{rDMPF}}.\mathsf{Setup}
      (\share A\in\mathcal X_N^t)\longrightarrow\mathsf{ready}$:
    \begin{enumerate}
        \item Reconstruct $A$ from the two submitted shares.
        \item If setup was already called, output $\bot$.
        \item Store $(A,q):=(A,0)$ and output $\mathsf{ready}$.
    \end{enumerate}
    \medskip

    $\mathcal F_{\mathsf{rDMPF}}.\mathsf{Expand}
      (\share B\in\mathbb G^t)
      \longrightarrow\share y\in\mathbb G^{[0,N)}$:
    \begin{enumerate}
        \item If setup has not completed, output $\bot$.
        \item Receive $y_b\in\mathbb G^{[0,N)}$ from the corrupt party $P_b$.
        \item Reconstruct $B$ from the two submitted shares.
        \item Output $y_{1-b}:=\mathsf{mp}_{N,t}(A,B)-y_b$ to $P_{1-b}$.
        \item Set $q:=q+1$ and retain $A$.
    \end{enumerate}
    \end{minipage}}

  Reusable distributed multi-point functionality.\label{fig:dmpfFunc}
}
\end{figure}

We use the same static semi-honest simulation convention as for
$\mathcal F_{\mathsf{rDPF}}$.  For either corrupt party $P_b$, the simulator
receives only public parameters and that party's input shares.  It generates
the corrupt view and submits $y_b$ to the functionality on each expansion.
For every polynomial $Q(\kappa)$ and every static semi-honest PPT adversary,
there must exist a stateful PPT simulator whose view, jointly with the
honest outputs, is computationally indistinguishable from the real execution
for at most $Q(\kappa)$ adaptively chosen payload vectors.
The simulator proceeds online without rewinding or receiving future inputs.
The view includes persistent local state, public values, messages, and
output shares.

An efficient realization must address three costs:

\begin{enumerate}
    \item \emph{Local expansion.} The dominant leaf work should be linear
    in $N$, with a small factor independent of $t$.
    \item \emph{Succinct key generation.} Communication should be sublinear
    in $N$, ideally $O(t\log N)$.
    \item \emph{Deduplication.} Payloads at duplicate indices must be aggregated
    without revealing which indices coincide.
\end{enumerate}

The sum-of-DPFs baseline is common in PCGs
\cite{boyle2020efficient,foleage,anyField,pcgZ2k}; its $tN$ leaf work can
dominate correlation generation \cite{foleage,libOTe}.
\sectionref{sec:cuckoo} reviews the sparse-column layout;
\sectionref{sec:waterfallCuckoo} gives Waterfall's generic realization with
$4N$ and $3N$ profiles. Bucketing and big-state methods offer other
setup--state tradeoffs in \sectionref{sec:bucketing} and
\sectionref{sec:bigState}.

The later Reverse-Cuckoo specialization in \sectionref{sec:revCuckoo}
does not realize the generic functionality above. It uses random Ring-LPN
supports and an additional leakage-robust decisional assumption to obtain
$2N$ expansion.
