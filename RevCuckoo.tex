
\section{Reverse Cuckoo DMPF}\label{sec:revCuckoo}

We solve the challenges of the cuckoo construction by completely eliminating the need to construct a cuckoo hash table $c$ using the interative method. Instead, we first choose a random cuckoo hash table $c$ and then to solve for consistent hash function $h_1,...,h_w$.

\paragraph{Overview} We will assume the reader is familiar with \sectionref{sec:cuckoo}. The core idea of our construction is as follows.

\begin{itemize}
    \item The idea is that we will first pad $\share{A},\share{B}$ to each be length $m$ with dummy values and then permute the list in a random order. The positions that each real item lands in will be the cuckoo position that each point belongs to. That is, $c_i=\pi(i)$ where $\pi$ is the random permutation. Let $\share{A'},\share{B'}$ now denote the permuted points.

    \item Our next goal is to construct hash function $h_1,...,h_w$ such that for some $j\in [w]$ it holds that $h_j(A_i)=c_i$ without revealing anything about the actual value of $A_i$.

    \item We then reinterpret each index $\share{A_i}$ as a binary vector in $\{0,1\}^{\log N}$ and partition $\share{A'}$ into $w$ region denoted as $\share{M_1},...,\share{M_w}\in \{0,1\}^{d\times \log N}$ where 
    $$
        \share{M_i}=\begin{bmatrix}
        \share{A'_{g+1}}\\
        ...\\
        \share{A'_{g+d}}
    \end{bmatrix}
    $$
    for $g:=(i-1)d$ and $d:=m/w$.

    \item The core idea will then be to construct a \emph{linear} ``hash function'' which maps $A'_i$ to its assigned position $i$. In particular, we want some vector $h$ such that $\langle h, A'_i\rangle =i$. More speficially, we want $w$ vectors $h_1,...,h_w$ where  for each $A'_i$ and some random $j$ it holds that $h_j(A'_i)=i$. 
    
    Since the $A'_i$s are in a random order, we can simply mandate that the first $d$ values will use $h_1$, the second $d$ values use $h_2$ and so on. Let us focus on $h_1$. The desired condition is simply
    $$
        \share{M_1}\cdot \share{h_1'}=\begin{bmatrix}
            1&
            2&
            ...&
            d           
        \end{bmatrix}^T
    $$
    We will choose a random $h_1$ which satisfies this. Moreover, we can perform all of this modulo $d$ and therefore all other $h_i$ can be derived using the same structure. Overall we obtain that
    $$
        \langle \share{A_i'}, \share{h_{\lfloor i/d\rfloor}}  \rangle= i \mod d  
    $$
    The $\mod d$ can then be manually offset. That is, some index $\alpha \in \{0,1\}^{\log N}$ is hashed to positions
    $$
        h_j'(\alpha) := (\langle \alpha, h_j \rangle \mod d) + 1 + (j-1)d
    $$

    \item Once the $\share{h_j}$ values are solved for, the parties can reveal them and use $h_j'$ to define the position matrix $P$. The rest of the protocol can the proceed as described before with the use of the Sparse DPF protocol for each column of $P$.
\end{itemize}

In summary, the parties first obliviously assign the $t$ input points to $m=(1+\epsilon)t$ positions. The parties then solve a set of $w$ linear systems to derive the hash function $h_1',...,h_{w}'$ which in turn defines the prosition matrix $P$ which can be used in conjection with the sparse DPF to complete the protocol. The full protocol is described in \figureref{fig:revCuckoo}.

\paragraph{Invertibility.} The description above assume that the system of equations $M_i$ is invertable. However, it is possible to choose a set of inputs $A_1,...,A_t$ for which their bit decomposition is not invertable. To address this issue we opt to first hash each index using some appropriately chosen hash function $H :\{0,1\}^{\log N}\rightarrow\{0,1\}^q$ where $q$ is sufficiently large that over the random choices of $H$ the resulting system is invertibable with overwhelming probaiblity, e.g. $q\geq d+\lambda$ for statistical security parameter $\lambda$. In \sectionref{sec:hash} we give a concrete suggestion for $H$.

\paragraph{Duplication.} Another complexity is that it is possible to have duplicate input indices $A_i=A_j$. In this case the ideal functionality will output $B_i+B_j$ at index $A_i$. However, the protocol as described only works for distinct $A_i$. Therefore we introduce a deduplication step at the start of the protocol which is explained in more detail in \sectionref{sec:dedup}.

Next we will present the neccessary subprotocols before a formal description and proof of security.

\paragraph{The reverse-cuckoo leakage channel.}
The revealed hash descriptors are not input-independent uniform strings, and
the difference is not only a cuckoo-failure bit.  The following idealized
calculation makes the leakage precise.  Fix a set $A$ of $t$ distinct active
items, let $U$ be the distribution obtained by giving every item one
independent uniform candidate in each of $w$ disjoint partitions of size $d$,
and let $Z_A(h)$ be the number of injective placements of $A$ in the resulting
cuckoo graph $h$.  A fixed injection into the $m=wd$ bins is compatible with
$h\gets U$ with probability $d^{-t}$, and hence
\[
    \mathbb E_{h\gets U}[Z_A(h)] = \frac{(m)_t}{d^t}.
\]
Reverse cuckoo instead chooses a uniform injection first and programs the
corresponding candidate of each item.  Summing over the injections compatible
with a fixed $h$ gives the exact likelihood identity
\begin{equation}\label{eq:rev-cuckoo-size-bias}
 \Pr[H=h\mid A]_{\mathsf{RC}}
   = \Pr[H=h]_{U}\,
     \frac{Z_A(h)}{\mathbb E_{U}[Z_A(H)]}.
\end{equation}
Thus the real distribution is size-biased by the \emph{number} of valid
placements; it is not $U$ conditioned merely on $Z_A(h)>0$.  Its information
density relative to the input-independent base $U$ is
$\log_2 Z_A(h)-\log_2\mathbb E_U Z_A(H)$.  This observation invalidates the
stronger claim that generic Reverse Cuckoo leaks only a negligible abort bit.

Equation~\eqref{eq:rev-cuckoo-size-bias} describes the standard random-function
model.  In the protocol, $h$ is represented by the revealed solutions to the
Goldreich-feature linear systems.  Let
$\mathsf{Leak}_{\mathsf{RC},N,t,w,d,B}(\mathcal A)$ denote the joint distribution of all public
hash descriptors in a batch of $B$ Reverse-Cuckoo instances on support lists
$\mathcal A$, including the shared fresh feature matrices used by the
implementation.  The definition includes the feature-rank bad event.  On the
event that every active feature submatrix has full row rank, randomized
\textsf{bin-solver} samples uniformly from the required affine solution
spaces; a zero or dependent active row is a proof-failure event, not a
protocol abort.  Dummy rows are omitted from this rank requirement because
$H_i(N)=0$ and \textsf{bin-solver} intentionally ignores them.

\paragraph{Leakage-robust Ring-LPN assumption.}
We use Reverse Cuckoo in the PCG only under the following explicit auxiliary
leakage assumption.  Sample $e,f\gets\mathsf{HW}_{\mathbb R,t}$,
$r,u\gets\mathbb R$, let $\mathcal A(e,f)$ contain every (possibly regularized
or product) support list supplied to Reverse Cuckoo by the PCG, and sample
$\Lambda\gets\mathsf{Leak}_{\mathsf{RC},N,t,w,d,B}(\mathcal A(e,f))$ jointly with those supports.
We assume
\begin{equation}\label{eq:ring-lpn-revcuckoo-leakage}
  (r,\;r e+f,\;\Lambda)
       \;\approx_c\;
  (r,\;u,\;\Lambda).
\end{equation}
The batched version quantifies jointly over all sparse polynomials and all
descriptors used in one PCG setup, rather than assuming that leakage from
different sets is independent.  For Stationary LPN, the same $\Lambda$ and
support are retained across the prescribed number of expansions while the
coefficients and ring masks refresh.  This is a falsifiable strengthening of
Ring-LPN/SSD with a fully specified, efficiently sampleable support-leakage
channel; we do not claim a reduction from plain Ring-LPN.

\paragraph{Security statement under leakage.}
For arbitrary inputs, Reverse Cuckoo realizes a leakage-augmented DMPF
functionality that outputs $\Lambda$ in addition to the DMPF output.  Given
$\Lambda$, standard semi-honest simulators for \textsf{dedup},
\textsf{bin-solver}, the permutation, and the sparse DPFs simulate the
remaining transcript, up to their usual cryptographic errors and the active
feature-rank bad event.  In the Ring-LPN and Stationary-LPN applications,
Equation~\eqref{eq:ring-lpn-revcuckoo-leakage} then hides the sparse noise even
given $\Lambda$.  Correctness is unconditional outside the rank bad event:
the programmed candidate sends every active item to its distinct designated
bin, after which the sparse DPFs sum to the requested multi-point function.

\paragraph{Concrete cuckoo failure.}
Failure of an input-independent table to admit a placement remains useful for
quantifying how far one would need to move toward ordinary cuckoo security,
but it is distinct from the size-bias leakage above.  Exact matching
experiments at the implementation's current two-choice parameters $d=t$ give
failure probabilities $0.0620,0.1005,0.1158$ for
$t=16,64,128$, respectively; this load is at the two-choice threshold and the
failure does not decay.  Enumerating all Hall witnesses gives conservative
40-bit parameter bounds.  For a batch of $B=256$ sets (hence a per-set target
$2^{-48}$), three choices with power-of-two partition sizes
$d=128,256,256$ for $t=16,64,128$ give log-base-two batch failure bounds
$-44.16,-44.71,-40.63$, respectively.  The corresponding two-choice sizes are
$32768,65536,131072$ and are not practical.  These are placement-failure
bounds only; Equation~\eqref{eq:ring-lpn-revcuckoo-leakage} is still required
for the support leakage.  Allowing four choices gives a better finite-size
tradeoff: $d=16,32,64$ for $t=16,64,128$ gives log-base-two batch bounds
$-43.83,-49.08,-60.01$.  The simpler schedule $d=2t$ gives still larger
margins $-59.90,-81.14,-92.02$, but is overprovisioned, particularly at
$t=128$.  Since each extra choice adds another domain-sized partition pass,
the best three-versus-four-choice point is ultimately a performance question.
The current implementation supports only $w\in\{2,3\}$, derives $d$ directly
from $(t,w)$, and does not use its \texttt{cuckooSecParam} argument; selecting
these bounds therefore requires generalizing $w$ and exposing $d$ (or a
validated failure target) in the initialization API.

\paragraph{Reverse Cuckoo subprotocols.}
Our Reverse Cuckoo DMPF relies on three standard MPC subroutines, a binary linear system
solver, a deduplication pass for colliding indices, and a lightweight hashing layer used only to
ensure the system is full rank.
These components are not strictly novel; the contribution is a careful implementation and integration
that yields an efficient setup.

\emph{System solver (bin-solver).}
Given secret-shared inputs $\share{M} \in \F_2^{m \times c}$ and $\share{y} \in G^m$ for a characteristic-$2$ group $G$,
the bin-solver outputs a secret-shared solution $\share{x} \in G^c$ such that $Mx=y$ (when solvable),
and samples a uniformly random solution within the affine solution space by randomizing free
variables and performing back-substitution. The protocol is based on standard elimination-style
row operations performed in MPC, and requires $O(mc+mc\log |G|)$ bits of communication. See \sectionref{sec:solver} for details.

\emph{Deduplication.}
Before solving, we remove duplicate keys among the $t$ secret-shared indices: for each key value,
the first occurrence accumulates the sum of payloads and subsequent duplicates are rewritten to a
public dummy key with zero payload. This ensures correctness under collisions while keeping the
subsequent placement and solving logic well-defined. The protocol uses standard MPC equality
tests and conditional moves.  See \sectionref{sec:dedup} for details.

\emph{Hashing layer.}
The hashing layer is seeded and block-local and is used only to ensure that, after shuffling, each
block matrix $M_i$ formed from hashed rows has full row rank over $\F_2$ with overwhelming
probability. We do not
require cryptographic properties such as collision resistance; we require post-hoc algebraic
genericity under fresh seeds sampled independently of the inputs. Our implementation uses an
Goldrich PRG styled construction that is linear except for a small number of bitwise multiplications.  See \sectionref{sec:hash} for details.
