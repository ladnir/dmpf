\section{Application to PCGs: Ring-LPN and Stationary LPN}\label{sec:ringlpn}

\paragraph{PCGs in a nutshell.}
A pseudorandom correlation generator (PCG) uses short seeds to generate a
long sample from a target two-party correlation $\mathcal C$.
Its interfaces are
\[
 \PCG.\Gen(1^\lambda)\longrightarrow(k_0,k_1),\qquad
 \PCG.\Expand(p,k_p)\longrightarrow R_p,
 \quad p\in\{0,1\}.
\]
Expansion is local and communication-free. Security concerns a semi-honest
corrupt party that knows its seed, not an observer given only the outputs
\cite[Defs.~2.5--2.6]{boyle2020efficient}.

We describe an interactive correlation-generation protocol built from
distributed sparse products and local ring arithmetic.
Its reusable setup fixes the sparse supports and initializes the DMPFs.
Each subsequent batch refreshes the coefficients and public masks, invokes
the DMPF expansions, and computes the OLE outputs.
Unlike $\PCG.\Expand$, these batches communicate; reuse amortizes only
the address-dependent setup. Security requires the joint stationary
assumption below and the distributed subprotocol guarantees.

The DMPF functionality guarantees a private sharing of the sparse product,
but does not require independently uniform output shares. The application
must separately establish the target correlation distribution and security
given a corrupt party's view.

\paragraph{Ring-LPN PCGs.}
Ring-LPN based \emph{silent} PCGs \cite{boyle2020efficient} and variants ~\cite{pcgQASD,foleage,anyField,pcgZ2k} work over a degree-$N$ ring $\mathbb{R}=\mathbb{F}_q[X]/(X^N+1)$ and use sparse noise
polynomials to derive many correlations at once. Each party samples sparse ring elements; both parties use the same fresh public mask
$r\leftarrow \mathbb{R}$. Party $p$ forms $x'_p=e_{p,0}+r\cdot e_{p,1}$ and applies an NTT to obtain
$x_p=\mathsf{NTT}(x'_p)\in \mathbb{F}_q^N$. The goal of the PCG is to produce an additive sharing of the ring product
$y'=x'_0\cdot x'_1$, which then maps locally to a packed OLE / triples relation $y=x_0\odot x_1$
after applying $\mathsf{NTT}$. Full details and notation are given in \sectionref{subsec:ringlpn}.%

\paragraph{Stationary LPN / SSD.}
Stationary LPN (SSD) \cite{Stationary} is the regime where the \emph{supports} of the sparse noises are fixed across many expansions, while the
\emph{coefficients} refresh each time. In the Ring-LPN PCG flow, this means the address patterns induced by the sparse products
are fixed once, and subsequent expansions differ only in the payload values and the fresh ring masks. This enables an
``offline/online'' split: perform all position-dependent preprocessing once, then, in each expansion, only inject new coefficients
and run ring/NTT arithmetic. We defer the formal statement and the amortization details to

\sectionref{sec:stationary}.%

\subsection{Impact on Related PCG Constructions}\label{sec:impact}

Sparse encodings also appear in programmable PCGs for Boolean circuits,
arbitrary finite fields, and Galois rings
\cite{foleage,pcgQASD,anyField,pcgZ2k}.
Waterfall is a candidate replacement when a construction needs the
multi-point sharing functionality defined here.
The benefit depends on the domain sizes, support distribution, and cost of
the surrounding arithmetic.

Such a transfer requires a separate argument for stationary reuse and,
if Reverse Cuckoo is used, descriptor leakage. The assumption analyzed here
is specific to the stated Ring-LPN distribution. We have not measured
end-to-end gains for these other applications.
